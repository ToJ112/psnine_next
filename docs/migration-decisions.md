# 历史功能到新实现的取舍

功能台账包含 80 个独立验收点，不是 80 个互不相关的新按钮；主题模式、同一图表的数据边界、v2/触屏兼容都分别核对。原仓库 README 仅是入口，完整能力以源码与历史为准。

## 保留并重新实现

全局主题/设置、内容过滤、帖子与问答增强、自动翻页、奖杯统计/汇总/排序、内联 Tips、个人进度、版本关联、约战监控、测评分析及数折功能均进入实现计划。README 漏列的进度缓存、约战铃铛、内联 Tips、图表折叠、白金封面和均分/热度趋势同样保留。

## 修复旧语义而不是复制旧故障

- 主站公开奖杯页没有个人状态时，标为未知；不推断所有奖杯未获得。
- 不用最早奖杯日期替代“时间丢失”；不把无效周/价格数据画成真实点。
- 用户名从登录 Cookie/账号导航确认，个人进度按账号保存。新脚本不能读取旧脚本的 GM 私有区，旧进度应重建；旧 localStorage 设置可迁移。
- 版本关系采用元数据或精确标题核对；不同版本的同序号奖杯不一定对应，链接前需核对名称/描述。
- 评分和黑名单筛选共同生效，切换分数不会重新显示被屏蔽的用户。
- 汇率注明日期、来源、过期状态，接口失败不使用静默历史常量。
- 新安装签到默认关闭；保留功能供用户启用。测试阶段只模拟其行为。
- 手机没有可靠的 hover，黑条、头像、回溯、图表都提供可点击/键盘可访问路径。

## 安装与更新方式

模块化只发生在源码中。`dist/psnine_next.user.js` 包含所有 JavaScript 和样式，不依赖项目目录，也不要求用户安装 Node。

仓库为私有；不在脚本头写入携带凭据的 URL，不依赖未登录的 GitHub raw 自动更新。下载新版本后在管理器中覆盖更新即可。新旧脚本不要同时启用，以免两套增强重复修改页面。
